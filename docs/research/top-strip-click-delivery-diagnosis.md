## Причина

Это явная политика подавления событий, а не попытка переслать клики в игру.

В [src/game-cursor-fence.c](../../src/game-cursor-fence.c), строки 792–800, `cursor_event_callback` при активном `MODE_CAPTURE` вычисляет:

```c
double protected_button_top = top_fence_y() + 0.5;
if (is_mouse_button &&
    gcf_capture_edge_should_suppress_button(location.y, protected_button_top)) {
    /* diagnostic log */
    return NULL;
}
```

[Политика](../../src/capture_edge_policy.c) возвращает `true` при конечных координатах и `location_y <= protected_top`. По умолчанию `fence_y=36.0`; `top_fence_y()` добавляет эту величину к верхней координате объединённых границ дисплеев. На конфигурации с верхом в `y=0` подавляется зона `y <= 36.5` в экранных пунктах, не обязательно физических пикселях.

Подавляются и down, и up для левой, правой и дополнительной кнопок. Обычные события движения продолжают возвращаться неизменными, кроме отдельного механизма подавления синтетического движения после однократной активационной парковки курсора. Когда захват неактивен, callback возвращает события без подавления.

Apple определяет возвращение `NULL` из `CGEventTapCallBack` как удаление события: [документация](https://developer.apple.com/documentation/coregraphics/cgeventtapcallback), также `CoreGraphics.framework/Headers/CGEventTypes.h:436–449` в локальном SDK. В этой ветке нет копирования и повторной отправки клика. Установленный бинарник содержит строку `capture-top-click-suppressed`; `nm -arch arm64 -u` не показывает импортов `CGEventPostToPid`, `CGEventCreateCopy` или `CGEventSetType`.

[README.md](../../README.md) и [Debag.md](../../Debag.md) прямо описывают подавление верхних кнопочных событий как часть ранее принятого исправления системного курсора и вертикального движения камеры RDR2. `tests/capture_edge_policy_test.c` специально ожидает подавление при `y=0` и `y=33`. Последний релиз содержит это же поведение, поэтому переустановка/обновление до 1.2.15 его не устранит.

## Воспроизводимый тест без воздействия на игру

Диагностический probe включал реальный `src/game-cursor-fence.c` с переименованным `main` и напрямую вызывал неизменённый `cursor_event_callback` на `CGEvent`, созданных только в памяти. Не устанавливались taps, не отправлялись системные события, курсор не двигался и не скрывался, сервис не перезапускался. Заглушён только запрос видимости курсора, чтобы исключить вызов глобального hide; состояние игры моделировалось через `g_active`. Подавление синтетической активационной парковки выключено в тестовых данных.

Команда, выполненная дважды:

```sh
/tmp/gcf-click-diagnosis.9AcnC7/top_click_callback_probe
```

Оба запуска завершились с кодом `1`: тест требует доставлять все down/up и обнаруживает описанную пользователем потерю событий.

| Y относительно верха дисплеев | Кнопки при неактивном захвате | Кнопки при активном захвате | Вертикальное движение |
| --- | --- | --- | --- |
| 0 | 6/6 | 0/6 | без изменений |
| 24 | 6/6 | 0/6 | без изменений |
| 33 | 6/6 | 0/6 | без изменений |
| 36 | 6/6 | 0/6 | без изменений |
| 36.5 | 6/6 | 0/6 | без изменений |
| 37 | 6/6 | 6/6 | без изменений |
| 100 | 6/6 | 6/6 | без изменений |

Контрольный эксперимент: только во временной копии исходника к условию выше добавлено `false &&`; все остальные ветки callback сохранены. Команда:

```sh
/tmp/gcf-click-diagnosis.9AcnC7/top_click_callback_probe_control
```

Результат: код `0`, **6/6** кнопочных событий во всех строках; движение и координаты остались неизменными. Это подтверждает причинность ветки подавления, но не доказывает, что простое удаление ветки безопасно в настоящей игре.

Временные диагностические материалы: `/tmp/gcf-click-diagnosis.9AcnC7/`. Они не входят в поставку и не являются внесённым исправлением; каталог может быть очищен системой.

## Альтернативные причины и проверки

1. **Явное подавление в helper — подтверждено.** Отключение только этой ветки устраняет потерю событий в callback.
2. **Ошибка координат либо выбор неправильного PID — не нужны для воспроизведения.** Событие удаляется раньше доставки/маршрутизации, без изменения координат. Особенности Wine/macOS всё ещё важны для будущего исправления и его E2E-проверки.
3. **Отсутствие разрешений — не объясняет данную селективность.** Read-only `CGGetEventTapList` обнаружил существующий HID filter (`point=0`, `options=0`) процесса `2041`, с кнопочными событиями в маске. Во время проверки tap был выключен, а `--check-frontmost` вернул `match=false`; отключение в idle соответствует основной логике приложения. TCC-настройки не изменялись и запросы разрешений не вызывались.

Шесть штатных проверок успешно выполнены: edge policy, watchdog policy, совместимость universal binary, defaults, provider detection и capture model. Они защищают существующее поведение, включая подавление кнопок, а не новое требование доставки кликов. Проверки бинарника запускались именно на установленном executable.

Старый `scripts/test_top_click_no_teleport.sh` ожидает прохождение кликов и лог `capture-top-click-forwarded`, то есть расходится с текущей принятой реализацией. Он не запускался: сценарий перезапускает сервис и отправляет реальные системные события; `--check-running` обнаружил matching process. Не проводилось тестирование физической мышью внутри реальной игры.

Диагностический C-код собран с явным `-isysroot` на Xcode SDK 26.5. Сборка без явного SDK сначала получила ошибку linker/TAPI `unknown architecture arm64e.x1-macos` из CLT SDK 27.0; настройки системы не изменялись.

## Что потребуется для исправления

Нельзя считать простое удаление `return NULL` готовым исправлением: исходная системная стрелка/обработка верхней плашки может вернуться.

Отдельный эксперимент должен обеспечить **ровно одну** доставку down/up в проверенный foreground Wine/game process, подавляя исходный небезопасный системный клик, если это необходимо. Возможный маршрут — кнопочная пересылка через `CGEventPostToPid`, но её работоспособность для конкретной игры ещё не проверена. Нужны защита от повторного перехвата и сбалансированная пара down/up, включая уход из защищённой зоны и смену фокуса.

Путь движения камеры следует оставить прежним: без повторной отправки motion, изменения delta/type и warp во время игрового ввода. Критерии E2E: игра получает один полный клик; системная стрелка не появляется; фокус не меняется; вертикальная камера не дёргается. Предыдущая просьба сохранить принятую реализацию зафиксирована в `Debag.md`; для изменения установленного приложения нужен отдельный запрос пользователя.
