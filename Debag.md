# Game Cursor Fence: accepted RDR2 camera fix

## Fixed behavior

RDR2 camera movement must continue smoothly when the physical mouse is moved vertically upward, even after the macOS pointer reaches the top of the display.
Strictly vertical physical input must remain vertical, and the helper must not add horizontal movement or require mouse clicks.
The system cursor must remain hidden when the user clicks at the protected top strip.

## Implemented fix

The accepted implementation uses capture mode and does not teleport the cursor while gameplay input is being processed at the upper boundary.
When a matching GameHub or Wine game becomes active, the helper hides the system cursor and calls `CGAssociateMouseAndMouseCursorPosition(false)` to detach physical mouse movement from the WindowServer cursor position.
The helper parks the hidden cursor once at a safe interior point when capture starts, before continuous gameplay input begins.
The synthetic motion generated by this one-time activation park is recognized and suppressed so Wine does not receive it as camera movement.

Every normal gameplay mouse-motion event is then returned to Wine unchanged.
The helper preserves the original event type, absolute location, `kCGMouseEventDeltaX`, and `kCGMouseEventDeltaY` fields.
It does not post a second PID-targeted copy, convert the event to a dragged type, rewrite the boundary coordinate, inject diagonal movement, or perform a live boundary warp.
Therefore a physical event with `dx=0` remains strictly vertical and reaches Wine without helper-generated horizontal motion or a synthetic downward correction.

At the protected top strip, the helper suppresses only mouse-button down and up events.
Normal motion events in the same strip continue through unchanged.
This prevents a top-edge click from exposing the macOS cursor without interfering with upward camera movement.

The visibility watchdog samples the real WindowServer cursor state from the main loop rather than mixing it with incoming HID coordinates.
If Wine exposes the cursor, the watchdog hides it again and restores detached capture only once for that visibility breach.
Repeated recovery is latched until the cursor has remained hidden for `0.5` seconds, which prevents rapid reassociation cycles from interrupting camera input.

When the matching game stops being active, the helper shows the cursor again, restores normal cursor association, and disables the capture event tap.

## Source locations

- `src/game-cursor-fence.c` implements activation capture, one-time safe parking, unchanged motion pass-through, synthetic park suppression, protected top-button suppression, and cleanup.
- `src/capture_edge_policy.c` decides whether a button event belongs to the protected top strip.
- `src/capture_watchdog_policy.c` implements the visibility-recovery latch.
- `tests/capture_edge_policy_test.c` verifies top-strip button suppression.
- `tests/capture_watchdog_policy_test.c` verifies one recovery per visibility breach and the stable-hidden reset.
